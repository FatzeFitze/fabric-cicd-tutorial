# Unit 8 preparation and pilot checks

10 November 2026. Unit 8 starts with an authenticated, read-only preflight of the existing shared Dev workspaces. It turns the Unit 7 duplicate-ID example into an API-backed check against independently recorded workspace names and live item inventory. [Unit 8 Part A](../tutorial/section-04-release-automation/unit-08-publish-shared-dev/README.md).

## Part A evidence

- **Runner and participant setup.** Learners create a manual ARM connection with workload identity federation and authorize just the preflight pipeline. The facilitator provides the UAMI and grants its Azure and Fabric access. Register the federated credential on the assigned UAMI with narrow delegation or a facilitator handoff. Use the Dev identity for preflight and first Dev publish. Confirm the actual connection, tenant setting and Viewer-or-higher assignment on all three Dev workspaces. [Workload identity service connection](https://learn.microsoft.com/en-us/azure/devops/pipelines/release/configure-workload-identity?tabs=managed-identity&view=azure-devops) · [Fabric identity support](https://learn.microsoft.com/en-us/rest/api/fabric/articles/identity-support).
- **Azure scope pilot.** The documented manual subscription path requires a subscription ID and name. `AzureCLI@2` selects that subscription when it starts. Confirm the smallest practical preassigned Azure role in the tenant by testing **Verify and save** and the actual task separately. Start with Reader on a dedicated training resource group in the specified subscription, keeping Fabric roles constant. Record the exact scope, which checkpoint passed or failed, and any subscription discovery or ARM verification error. Reader at resource-group scope is a pilot candidate. Azure Contributor is broader than the preflight's Fabric-only operations require. [Manual ARM setup](https://learn.microsoft.com/en-us/azure/devops/pipelines/release/configure-workload-identity?tabs=managed-identity&view=azure-devops) · [Azure CLI task implementation](https://github.com/microsoft/azure-pipelines-tasks/blob/master/Tasks/AzureCLIV2/azureclitask.ts).
- **Environment inputs.** The organizer asked for names and resource identifiers to be configurable per team and project. `config/environments/dev.yml` supplies the expected UAMI, service connection and workspace names. The connection name resolves at template expansion. The preflight records the configured identity labels and uses the service connection's authenticated session. Check the actual UAMI binding in the Azure DevOps connection. The release mask remains the source for repository references, revisions and workspace IDs. [Azure Pipelines variable templates](https://learn.microsoft.com/en-us/azure/devops/pipelines/yaml-schema/variables-template?view=azure-pipelines).
- **Documented calls.** Get Workspace and List Items support service principals and managed identities with a sufficient workspace role. The check compares the returned workspace ID and display name against the configured ID and assigned inventory. It lists items by role and matches type and display name exactly. The log records physical and available logical IDs. A successful read supplies access evidence for those calls. Write, execution and data access require separate evidence. [Get Workspace](https://learn.microsoft.com/en-us/rest/api/fabric/core/workspaces/get-workspace) · [List Items](https://learn.microsoft.com/en-us/rest/api/fabric/core/items/list-items).
- **Locally rehearsed.** Mock responses confirmed all three workspace comparisons and six observed item IDs across paginated results. The preflight rejected a wrong display name for a valid ID, a missing item and a repeated pagination token. Tests inspected the fixed Fabric API origin, GET method, Azure CLI token request and sanitized HTTP failure. A follow-up check verified the pipeline and preflight point to the same environment file, the configured identity labels appear in mock run evidence, and missing or unfilled required values fail before the preflight requests a Fabric token. Azure DevOps template expansion, connection authorization and Fabric access still need the live run.
- **Pilot evidence to retain.** Record the merged revision, pipeline identity, actual workspace and item IDs, active Dev set and the four exported dependency representations. Preserve any pending changes in the Dev workspaces for the cutover. The worksheet holds participant observations and the repo log should contain only sanitized findings.
- **MS coverage.** MS-04/06 for environment and workspace identity, MS-07/12 for authenticated access boundaries, and MS-14 for source and live inventory correlation.
